PII-BR: detecting and masking personal data in Brazilian Portuguese

Nov 23, 2026

Teams that need to anonymize logs, tickets, e-mails or contracts written in Brazilian Portuguese under the LGPD (Brazil's data protection law) usually end up with a handful of hastily written regexes. A regex finds a CPF (the Brazilian taxpayer ID), but it does not find "Maria Aparecida Souza" or "Rua das Flores, 123, ap. 42". Presidio, the reference open source PII detector, finds names and addresses, but it has no recognizer for CPF, CNPJ (company ID), RG (state ID) or CEP (postal code).

I wrote PII-BR to combine the two. It is a Python package that pairs deterministic rules, which check digits, area codes and postal codes, with an NER model trained on Portuguese, and then masks what it found. The code, the dataset and the model are open, and the demo runs entirely in the browser.

Concepts

Personal data, anonymization and pseudonymization under the LGPD

Under the LGPD, personal data is any information related to an identified or identifiable natural person (art. 5, I). Names and CPFs are personal data, and so are phone numbers and addresses, because they lead to the person. Anonymized data is data that does not allow the data subject to be identified with the reasonable technical means available (art. 5, III), and only that stops being personal data (art. 12). Pseudonymization replaces the data with something that only points back to the person with information kept separately (art. 13, § 4), such as an HMAC key. Pseudonymized data is still personal data.

Check digits

CPF and CNPJ numbers end in two digits computed from the previous ones with mod 11. A number with the right format and wrong final digits is not a valid document. That lets the regex tell a CPF apart from any eleven digits, which the format alone cannot do.

NER and BIO labels

Named entity recognition (NER) means classifying each word of a text as part of an entity or not. In the BIO scheme, B-NOME marks the first word of a name, I-NOME the following ones and O anything that is not an entity, so "Maria Aparecida Souza" becomes B-NOME I-NOME I-NOME. BERT models split words into subtokens (WordPiece), and the label goes on the first subtoken of each word.

Spans, precision and recall

A span is a stretch of text, with a start and end in characters and a label (CPF, NOME). Precision is the fraction of detected spans that were right; recall is the fraction of the real personal data that was found; F1 is the harmonic mean of the two. For masking, recall matters more: a false positive hides a word for nothing, and a false negative leaves personal data in plain sight.


What it detects

There are nine entities. The ones with a fixed format go to the rules, and the ones that depend on context go to the model. CPF, CNPJ and phone numbers go through both. 

ENTITY      EXAMPLE                        DETECTION
NOME        Maria Aparecida Souza          model
CPF         123.456.789-09                 regex + check digits + model
CNPJ        12.ABC.345/01DE-35             regex + check digits + model
RG          12.345.678-9                   model + context
TELEFONE    (11) 98765-4321                regex + valid area code + model
EMAIL       maria.souza@example.com        regex
ENDERECO    Rua das Flores, 123, ap. 42    model
CEP         01310-100                      regex + context
DATA_NASC   nascida em 03/07/1990          model

The labels are in Portuguese because they are the package's own entity names: name, phone, address and date of birth.

The rules

CPFs are validated with mod 11, and repeated sequences such as 111.111.111-11 are rejected. CNPJ accepts both formats: the numeric one and the alphanumeric one the Federal Revenue started issuing in July 2026 (IN RFB nº 2.229/2024). In the alphanumeric format, the first 12 positions accept [0-9A-Z], each character is worth ord(c) - 48 in the calculation, and the two check digits stay numeric. By that math, 12.ABC.345/01DE-35, the Revenue's official example, is valid.

A phone number needs one of the 67 area codes in use in Anatel's numbering plan and either the landline format (8 digits, starting with 2 to 5) or the mobile one (9 digits, starting with 9). Business numbers such as 0800, 0300 and 4004-xxxx are left out because they do not identify a person. A CEP only counts when it appears near a context word, because eight loose digits could be anything.

A document with the right format and a wrong check digit raises a "possibly invalid document" warning and is masked anyway. It may be a real CPF typed with one mistake, and leaving it visible is the most expensive error.

The model

The model is a fine-tune of BERTimbau base, with BIO labels on the first subtoken of each word. Long texts are read in 256-token windows with an overlap of 64. The confidence threshold (0.5) applies only to the model and runs before the merge, so a weak guess never wipes out a regex finding.

To run on CPU, the model is quantized to dynamic int8. Quantizing every linear layer breaks it: recall drops by half and scores hover around 0.3. The culprit is the FFN output of each layer (layer.N.output.dense), so those layers stay in fp32 and the rest goes to int8. The ONNX export script fails if int8 loses more than 0.5 F1 points against fp32.

The merge

Each model span is compared with the regex spans it overlaps. When both have the same label, a single span comes out, with source ambos ("both") and the regex boundaries, which are more precise for fixed formats. A CPF or CNPJ with valid check digits beats the model. The model wins for names, addresses and RG. In every other case the longer span stays.

The merge never exposes a character that some span covered. The model only replaces a regex span it covers entirely. If the model marks only -100 of CEP 01310-100 as an address, the regex CEP stays and 01310 does not show up in the masked text.

Masking

There are four strategies. Redaction replaces the value with the label ([CPF]). Partial keeps part of the value (***.456.789-**), which helps debugging without exposing the whole document. Pseudonym replaces the value with a stable identifier (<CPF_1>), computed with HMAC-SHA256 and a secret per-session salt, so the same CPF gets the same pseudonym on every line of a CSV. The salt is needed because there are only one billion CPF bases, and an unsalted hash can be reversed by brute force. Synthetic generates a random value that passes validation, useful for test databases.


The dataset

A real corpus full of personal data would be exactly what the LGPD tells you to protect, so the PII-BR dataset is synthetic: 38 thousand sentences generated from templates across 8 domains (customer support, WhatsApp, e-mail, contracts, sign-up forms, tickets, logs and police reports). Since the generator inserts every value, the annotation is correct by construction, and the whole dataset can be rebuilt from a seed.

The risk with a synthetic dataset is that the model learns the templates instead of the task. That is why evaluation uses three splits:

  1. test: the same templates as training, with new values. It is the most optimistic number.
  2. test_hard: templates the model has never seen.
  3. test_real: about 200 sentences I wrote by hand, outside the template system. It is the closest to real use.

Training takes about 30 minutes on a free Kaggle T4 GPU (lr 5e-5, up to 4 epochs with early stopping, batch 16, fp16). On my machine, which has no GPU, the same run would take around 16 hours.


Results

Span-level metrics, counting a hit when the label matches and the span overlaps the reference, which is what matters for masking. On test_real: 

SYSTEM                               PRECISION  RECALL   F1
hybrid (int8 model + regex)          0.939      0.990    0.964
model only (int8)                    0.928      0.955    0.941
model only (fp32)                    0.928      0.960    0.944
regex only (the package, no model)   0.989      0.450    0.619
Presidio (default, spaCy pt)         0.595      0.604    0.600

The regex is almost never wrong when it finds something (0.989 precision), but it finds only half the data, because it cannot see names, addresses or dates. Presidio scores 0% on CPF, CNPJ and CEP, since it has no recognizer for them. The hybrid reaches 0.990 recall, and on test_real per-entity recall is 1.000 for every entity except names (0.986) and CEP (0.917). Int8 quantization cost 0.003 F1. Median hybrid latency on CPU is 0.25 s for a 720-character text.

Most of the remaining errors are false positives, and many come from logs. An NF-e (electronic invoice) key, an IP address and a Pix transaction ID were tagged as CPF, which pulls CPF precision down to 0.840 on test_real. A license plate became an RG, and "Bairro Vila Industrial" became a separate address. On the false negative side, the errors that let personal data through, there was a CEP inside a log URL (GET /v2/zipcode/93228670) and the "Santos" in "Cb. Santos", which the model did not recognize as a name.


The in-browser demo

The plan was a Gradio demo on a free Hugging Face Space. In November 2026, Hugging Face started requiring a paid plan for Gradio and Docker Spaces, and only static Spaces stayed free. So the demo became a static page that runs everything in the browser.

The pii_br core uses only the Python standard library, so it runs on Pyodide (CPython compiled to WebAssembly) without changes. The model was exported to ONNX in int8, at about 190 MB, and runs on onnxruntime-web. WordPiece tokenization and window decoding are written in pure Python, in the same file the package uses outside the browser, so the demo and the library run the same code. Pyodide and onnxruntime-web are pinned to exact versions with SRI, and the model is pinned by commit.

Text pasted into the demo never leaves the visitor's machine, because there is no server. The first visit downloads about 200 MB (model and Pyodide), which stays in Cache Storage afterwards. While the model loads, the page works with the rules only. A 1,000-character text takes about 2 s, because the static Space does not send the headers that would enable WebAssembly threads.


Hands-on

Installation comes straight from the repository. The core has no dependencies, and the model is the [model] extra: 

pip install "pii-br[model] @ git+https://github.com/brennocm/PII-BR"
from pii_br import Detector, Masker
from pii_br.model import NerModel

detector = Detector(NerModel("brennocm/PII-BR"))  # without a model, Detector() uses only the rules
texto = "Sou Ana Lima, CPF 123.456.789-09, whats (11) 98765-4321."
spans = detector.detect(texto)

masker = Masker()  # one secret salt per session
masker.mask(texto, spans, "redact")     # Sou [NOME], CPF [CPF], whats [TELEFONE].
masker.mask(texto, spans, "partial")    # Sou [NOME], CPF ***.456.789-**, whats (**) *****-4321.
masker.mask(texto, spans, "pseudonym")  # Sou <NOME_1>, CPF <CPF_1>, whats <TELEFONE_1>.
masker.mask(texto, spans, "synthetic")  # Sou Gabriela Reis, CPF 609.746.327-83, ...

The synthetic value is random and passes validation, so it may match the CPF or phone number of a real person. It is meant for test data. To publish a text, use redact or pseudonym.

To run the project locally, the repository uses mise and uv: 

mise install && mise run setup                   # dependencies + pre-commit hook
mise run dev                                     # Gradio app at http://127.0.0.1:7860
mise run web                                     # Space demo at http://127.0.0.1:8000
uv run python -m data_gen.generate --out data    # builds the dataset (reproducible by seed)

The local Gradio app accepts .txt and .csv uploads, which the static demo does not.


Limitations

The model was trained only on synthetic data. test_real measures the gap to real text, but it has about 200 sentences and is a signal, not a guarantee. Names without context ("Jorge chegou") and names that are also common words are the hardest cases. RG has no national format, so the model relies on words such as "RG" and "identidade" near the number.

PII-BR does not cover the sensitive data in art. 5, II of the LGPD (health, religion, sexual orientation), nor license plates, cards, PIS or CNH (driver's license).

And it does not certify anonymization. Under art. 12 of the LGPD, anonymized data is data that cannot be reversed by reasonable means, and masking entities does not remove quasi-identifiers such as job title, neighborhood and dates. Use PII-BR to reduce risk, with human review where the text matters.


Final thoughts

Rules and the model fail in different places. The regex is precise and blind to context; the model understands context but still tags an NF-e key as a CPF. On test_real, combining them raised F1 from 0.619 (rules only) and 0.941 (model only) to 0.964.
